## 0. BLUF

> **NDA로 설문 응답 수집·활용이 금지됐다(2026-08-06 확인). 설문 트랙을 종료한다.**
> 본확산은 시행하지 않는다. T2 페르소나 승격/기각 판정은 **미실행**으로 동결한다.
> **VOC 74,434건 기반 결과물은 전부 유효하다** — 설문과 별개 계보다.

무게중심은 이렇게 바뀐다: 타깃 검증 축이 사라지고 **고객 발견(VOC 실측) 축만 남는다.**
이것을 숨기지 않고 발표에서 먼저 밝힌다. 프로젝트 서명("미구현을 미구현이라 표기한다",
"모르는 것은 수치화하지 않는다")과 정합하며, 검증하지 않은 것을 검증한 척하는 것이
이 프로젝트에서 유일하게 치명적인 실패다.

## 2. 죽는 것 — 설문이 떠받치던 사슬

```
설문 → 04_segmentation → seg_manifest(source_type=survey)
     → ThinQ Village 합성패널(실모드) → PERSONA_LADDER §5 승격/기각
```

[synthetic_panel.py](../synthetic_panel.py) L112~120이 `data/survey.csv` **실해시 대조**를
강제하므로, 설문 없이는 합성패널 실모드가 구조적으로 열리지 않는다. 게이트가 제 일을
한 것이므로 우회하지 않는다.

| 잃은 것 | 조치 |
|---|---|
| **Pain 3종 일반화 검증** (설문 목적 ②) | **주장 금지** — §2.1 참조. Pain의 **존재** 근거는 무사하나 **일반화**는 못 한다 |
| T2 페르소나(맞벌이·Quietly Home) 승격/기각 판정 | **미실행 동결** — "가설 — 검증 미실행(NDA)"로 병기 |
| H1(유자녀·야간 세그먼트 분리) 검정 | 미실행 |
| H2(주거 점유·이사 계획) 검정 | 미실행 |
| H3(묶음 구매·공유 니즈) 검정 | **검증 불가** — §3 참조 |
| `FEATURE_COLUMNS` 설문 기반 확정 | 미확정 유지 |
| ThinQ Village 실모드 | 불가. hypothesis 모드만 가능(발표 미사용) |

### 2.1 Pain Point는 무사하다 — 단, 일반화는 아니다 (파티 2026-08-06)

**계보가 완전히 분리돼 있다.** `painpoints.csv`는 `run_id 20260721_161447_227700`에서
나왔고 **설문 파일이 이 파이프라인에 들어간 적이 없다.** P-1 43.4% · P-2 1.37%(경쟁
2.0배) · P-3 6.2%와 POV·HMW 3개는 전부 유효하다.

**그러나 설문 목적 ②가 "Pain 3종 일반화 검증"이었다**(SURVEY_PLAN §0).
리뷰 표본 **밖**에서도 같은 Pain이 나타나는지를 재려던 축이 함께 죽었다.

> **선을 정확히 그어라:**
> "이 Pain이 **존재한다**" — ✅ 공개 리뷰 실측으로 증명됨
> "이 Pain이 **전체 사용자에게 나타난다**" — ❌ 검증 미실행. **주장하지 않는다**

#### 예상 질문 — 선택 편향 (면접에서 가장 날카로운 지점)

> **"리뷰는 화난 사람만 쓰지 않나요? 43.4%가 전체 사용자 얘기인가요?"**

방어 논리 3종은 **이미 데이터 안에 있다** — 새로 만들 필요 없다:

| # | 방어 | 근거 |
|---|---|---|
| 1 | **대조군 상대 비교** | P-2를 SmartThings와 비교(1.37% vs 0.67%). 편향은 양쪽에 동일하게 걸리므로 **절대값은 몰라도 2.0배라는 상대 비교는 살아남는다** |
| 2 | **시계열 안정성** | P-1이 **11년 전 구간에서도 유지** — 특정 사건(2026.07 사태) 의존이 아님 |
| 3 | **강점 동시 수집** | `strengths.csv` 전부 평점 5(다기기 호환·원격 조작·원격 모니터링). **불만만 긁었으면 이게 안 나온다** |

**답변 문안 (확정):**

> "네, 리뷰는 편향된 표본입니다. 그래서 **절대 수치를 사용자 전체로 일반화하지
> 않았습니다.** 대신 ①경쟁사 대조군으로 상대 비교 ②11년 시계열로 사건 의존성 배제
> ③강점 데이터 동시 수집으로 방향 편향을 점검했습니다. 일반화 검증은 설문으로 하려
> 했으나 NDA로 중단됐고, **그래서 일반화 주장은 하지 않습니다.**"

**세 박자를 지켜라: 약점 먼저 인정 → 그럼에도 한 것 → 못 한 건 못 했다고 끝.**

## 4. 대체 경로 (A + B, daria 승인 2026-08-06)

### A. 타깃 검증 "미실행" 정직 표기 — 주 경로

- T2 항목 전부에 **"가설 — 검증 미실행(NDA)"** 병기.
  기존 "가설 — 설문 검증 대기"는 **대기가 아니라 종료**이므로 문구를 교체한다
- T1 Night Keeper는 **VOC 실측 근거까지만** 주장. 인구통계는 여전히 없음을 명시
- H3는 "가설 제기됨 · 검증 불가(표본 없음)"로 남긴다. 기각이 아니다 —
  **기각도 검증의 결과이므로, 검증하지 않은 것을 기각이라 쓰지 않는다**
- 발표에서 먼저 밝힌다(§6 워딩)

### B. 공개 2차 자료로 배경만 보강 — 보조 경로

새 데이터 수집이 아니므로 NDA 무관. biz-docs의 `[공개출처]` 라벨 규약을 그대로 쓴다.

> biz-docs R-5)이므로, 수치마다 원출처 재접속 대조를 거쳤고 **확인 실패분은 제외**했다.

**B의 한계를 문서마다 병기한다: 이것은 검증이 아니라 정황이다.**
2차 자료는 "이런 집단이 얼마나 있는가"에 답할 뿐, "그들이 이 Pain을 겪는가"에는
답하지 못한다. 후자가 설문의 몫이었고, 그 자리는 비워둔다.

## 6. 발표 워딩 (확정)

### 6.0 데이터 출처 정본 워딩 — 반드시 이대로 (파티 2026-08-06)

> ## **"공개 앱스토어에서 직접 크롤링한 리뷰 74,434건"**

세 요소가 한 줄에 다 들어가야 한다: **출처**(공개 앱스토어) · **방법**(직접 크롤링) ·
**규모**(74,434건).

| ❌ 쓰지 말 것 | 왜 |
|---|---|
| **"고객 데이터로 분석했습니다"** | 듣는 사람은 **사내 고객 데이터**로 듣는다. NDA로 설문을 접은 상황에서 이 말이 나오면, 지켜서 접은 사람이 아니라 **막 갖다 쓴 사람**으로 읽힌다. **정직 표기 문제가 아니라 daria 본인 리스크 관리 문제다** |
| "크롤링으로 뽑았습니다" (출처 없이) | 방법만 있고 출처가 없어 **"어디서요?"**를 반드시 부른다 |
| "VOC 데이터" (뭉뚱그림) | 정보량 0. 74,434라는 숫자가 훨씬 세다 |

**"크롤링"은 빼지 않는다.** 출처가 앞에 붙는 순간 오해가 차단되고, 기술 면접관에게는
**남이 준 CSV를 받은 게 아니라 직접 수집했다는 실행 증거**가 된다.
부수 효과: "공개"라고 말하는 순간 **재현 가능성**이 생겨 방법론이 전달된다.

### 쓸 것

> "타깃 검증용 설문은 **NDA 제약으로 시행하지 못했습니다.** 그래서 페르소나 T2는
> 가설 상태 그대로 두었고, 승격도 기각도 하지 않았습니다 — **검증하지 않은 것을
> 기각이라 쓰지 않는 것이 이 프로젝트의 규칙**입니다."

> "대신 **고객 발견 축은 실측으로 끝까지 갔습니다** — 공개 리뷰 74,434건을 수집·분석해
> Pain Point를 정량 도출했고, 그 위에 PoC를 세웠습니다."

> "H3(신혼·묶음 구매 가설)는 리뷰 12,585건에서 혼수 4건·입주 2건으로 **표본 자체가
> 없다는 것을 확인**했습니다. 없다는 사실도 결과로 보고합니다."

### 금지

| 금지 표현 | 이유 |
|---|---|
| **"고객 데이터"** | §6.0 — 사내 데이터로 오해된다. **"공개 앱스토어에서 직접 크롤링한 리뷰"** |
| "사용자의 43.4%가 ~" | Pain 일반화 미검증. **"부정 리뷰의 43.4%"** 로 분모를 명시 (§2.1) |
