# 04. 요구사항 정의서 — ThinQ OnMe 실기기 PoC

> **AI 초안 — 최종 책임은 팀.** 주필 John · 부필 Sally · 2026-07-29
> 배경·문제 정의는 [01_사업기획서](01_사업기획서.md) §2를 승계한다.
> 상세 기술 명세는 [05_기술사업요구사항명세](05_기술사업요구사항명세.md).

## 1. 목적

시뮬레이터로 검증된 온바디 홈 프로필을 **실기기(워치+가전)에서 재현**하고,
시뮬레이터 가정값(BLE MTU·저장 예산·전환 시간)을 실측치로 대체한다.

## 2. 이해관계자와 요구 원천

| 이해관계자 | 요구 원천 | 성격 |
|---|---|---|
| 최종 사용자 | `[실측]` VOC 7,625건 (P-1/P-2/P-3), 페르소나 2종 (Night Keeper T1 · Quietly Home T2) | 기능 요구의 뿌리 |
| 발주 팀 | 시뮬레이터 PoC 계약 — 스키마·캐리어 인터페이스·보안 산출물 4종 | 제약 조건 |
| 검수 체계 | G 감사 게이트, 테스트 426 passed 회귀 유지 | 인수 기준 |

## 3. 기능 요구사항 (FR)

| ID | 요구 | 근거 Pain | 검증 방법 |
|---|---|---|---|
| FR-1 | 워치에 홈 프로필 저장 — 키당 4,096B, 총 128KB 이내 | P-2 | 실장 후 스토리지 실측 |
| FR-2 | BLE 근접 시 프로필 기반 기기 제어 (서버 무경유) | P-1 | 기내모드 서버 차단 시연 |
| FR-3 | 프로필의 신규 환경 이주 (기기 맵핑 재결합) | P-2 | 이사 시나리오 데모 재현 (`demo_relocate` 실기기판) |
| FR-4 | 무계정 로컬 온보딩 — 동의 범위 로컬 한정 | P-3 | CONSENT_SCOPE 대비 요구 항목 diff = 0 |
| FR-5 | 프로필 폐기·복구 (분실 시나리오) | 신뢰 전제 | REVOCATION.md 절차 재현 |
| FR-6 | 다인 가구 각자 프로필 실행 (부부 2프로필) | Quietly Home | `demo_quietly` 실기기판 — 충돌 해소는 범위 외 명시 |

## 4. 비기능 요구사항 (NFR)

| ID | 요구 | 기준 | 성격 |
|---|---|---|---|
| NFR-1 | 릴레이/재생 공격 방어 | THREAT_MODEL.md 방어 항목 + 잔여 한계 문서화 | `[실측]` 위협 모델 존재 |
| NFR-2 | 근접 제어 지연 | 목표 2초 이내 `[가정 — 실측으로 확정]` | 실측 대상 |
| NFR-3 | 정직 표기 | 미측정·미검증·시뮬레이터 값의 라벨 유지 — 산출물 전체 | 프로젝트 헌법 |
| NFR-4 | 벤더 격리 | 워치 벤더 API가 코어에 새지 않을 것 — 경계 테스트 통과 | `[실측]` CARRIER_INTERFACE |

## 5. 범위 제외 (명시적)

- 멀티 프로필 **충돌 해소·권한 모델** — Epic급 신규 설계, 별도 과제 (DECISIONS.md 등재)
- 위치 기반 도착 전 원격 준비 — 스키마 금지 항목(lat/lon), 프로젝트가 반박한
  서버 경유 구조의 재도입이므로 영구 제외
- 클라우드 백업 — 데이터 소재 원칙(DATA_RESIDENCY) 위반

## 6. 인수 기준 총칙

각 FR/NFR의 검증 방법 열이 곧 인수 시험 항목이다. 외주사는
[07_RFP](07_RFP.md) §6의 검수 절차에 따라 시연·실측 보고서를 제출한다.
