# ThinQ OnMe — EXPERIENCE.md (데모 프레젠테이션 층)

> **AI 초안 — 최종 책임은 팀.** 충돌 시 본 문서와 DESIGN.md가 우선한다.
> 범위: DEMO_SCRIPT §6~§12의 7개 장면 + 손목 1장 스케치. **그 외 화면 창작 금지.**

## Foundation

- **form-factor**: 발표장 프로젝터에 비친 **터미널** (CLI 프레젠테이션 층).
  워치·폰 제품 UI가 아니다 — 제품 UI는 "손목 1장" 스케치(설계안·미구현)로만 존재.
- 조작 주체는 **발표자**다. 관객은 조작하지 않는다. 따라서 상호작용 설계의 단위는
  "클릭"이 아니라 **"명령 한 줄 실행 = 장면 하나"**.
- 시각 계약은 {colors.terminal.*}, {typography.terminal.*} (DESIGN.md).

## Information Architecture

7개 장면, 대본과 1:1. 순서는 서사이므로 변경 금지:

| # | 장면 | 명령 | 겨냥 | 층의 핵심 과제 |
|---|---|---|---|---|
| S1 | 🌙 야간모드 (절정) | `demo_night.py --offline` | P-1 43.4% | Job 문장 + 전이 4행의 가독 |
| S2 | 재설치 복원 | `demo_reinstall.py --offline` | P-2 | 실측 리뷰 인용 → 3장면 리듬 |
| S3 | 이사 매핑 | `demo_relocate.py` | P-2(다른 축) | 이전+보류=전체, 누락 0의 시각화 |
| S4 | 무계정 온보딩 | `demo_onboard.py --offline` | P-3 6.2% | "요구하는 것 vs 않는 것" 대비 |
| S5 | 데이터 소재 | `demo_residency.py --offline` | P-3 완성 | 소재 4행 표 + 한계 표기 |
| S6 | 릴레이 방어 | `demo_relay.py` | 위협 모델 | 막는 것/못 막는 것 동일 무게 |
| S7 | 폐기 | `demo_revoke.py --offline` | "잃어버리면요?" | evidence_block — 배지 금지 |

모든 장면에 `honesty_footer` (시뮬레이터/참조 어댑터 · 실기기 아님 · 장면별 한계).

## Voice and Tone

- 화면 문장은 대본 §6 "말해도 되는 것" 열의 화법만 사용한다. 무조건형 금지.
- 고정 마이크로카피 (대본·파티 점검에서 확정):
  - S2: "참은 게 아니라 개입할 자리가 없다"
  - S3: "조용히 버리지 않는다 — 보류에는 사유가 붙는다"
  - S4: "계정을 참는 게 아니라 만들 자리가 없다"
  - S5: "옮길 수 없는 게 아니라 옮길 **것이 없다**" (부재의 증명 — Mary 프레이밍)
  - S6: "완전 제거가 아니라 표면 축소"
  - S7: "지웠다는 보고를 믿지 않고 복원을 시도해 검증한다"
- 금지 문장은 대본 §6 우측 열 그대로 승계 (❌ "네트워크 캡처로 확인" 등).

## Component Patterns (behavioral)

- **scene_header** — 장면 진입 시 1회. 겨냥 Pain의 수치는 실측 출처가 있는 것만
  (P-1 43.4% ✓ / P-3 6.2% ✓). 출처 없는 수치 표기 금지.
- **transition_row** — 전이 발생 순간 1행씩 출력(일괄 덤프 금지 — 발표자가
  행 단위로 말을 얹을 수 있어야 함). 형식: 기기 / 전이 / 판정 / Job 대응.
- **evidence_block** (S7 전용) — 검증 축 2개를 분리 표기:
  `축1 복원 시도 → ✗ 실패 (증거)` / `축2 잔류 스캔 → 0건 (증거)`.
  "폐기 완료" 문자열은 두 축이 모두 통과한 뒤에도 **출력하지 않는다** —
  두 증거 행 자체가 결론이다.
- **boundary_table** (S6 전용) — 못 막는 것 3항(실시간 relay·근접 위조·탈취 즉시
  사용)을 막는 것과 같은 행 높이로. 탈취 항목에는 "→ 폐기는 S7" 연결 표기.
- **held_summary** (S3 전용) — 이전 n + 보류 m = 옛 전체 N 항등식을 표로 출력.
  보류 각 행에 사유 필수.

## State Patterns

- 판정 상태는 3값: ✓ 성공(success) / ✗ 차단·거부·실패(blocked) / ⏸ 보류(held).
- ✗는 두 의미로 쓰인다 — **증거로서의 실패**(S1 소켓 차단, S6 재생 거부, S7 복원
  실패: 바라던 결과)와 **폴백 상황**(BLE 불가 → 루프백). 후자는 반드시
  "루프백 — BLE 아님" 정직 표기와 함께 (대본 §7 폴백 규칙).
- 어느 상태에서도 **동작한 척 금지** — 폴백을 썼으면 화면에 폴백이라 적는다(NFR6).

## Interaction Primitives

- 명령 한 줄 = 장면 하나. 장면 내 추가 입력 없음(발표 리듬 보호).
- 장면 사이 전환은 발표자의 다음 명령 실행 — 자동 진행 금지.
- S1 직후 기내모드 전환은 **사람이 장비에서 누른다**(대본 §3) — 층은 이를
  대신하지 않고, 전환 후 재실행 성공을 보여줄 뿐이다.

## Accessibility Floor

- 프로젝터 뒷줄 가독이 유일한 접근성 목표: 최소 폰트 크기 (검증 필요 — 리허설
  실측), 색 판정에 항상 기호 병기(✓/✗/⏸ — 색맹 대비), 한 화면 한 장면.

## Key Flows

### F1 — Night Keeper의 밤 (S1, 발표의 절정)

Night Keeper(잡 기반 페르소나 — **인구통계는 설문 검증 대기**)가 잠들기 전:

1. Job 문장이 화면 상단에 뜬다 — "내가 잠든 뒤에도 집이 아이를 지킨다"
2. `--offline` 차단 증거: 소켓 열기 시도 → ✗ 실패 (적색, 증거)
3. **클라이맥스**: 전이 4행이 1행씩 — 에어컨 조용히 ✓ → 청소기 끔 ✓ →
   조명 끔 ✓ → 냉장고 잠금 ✓, 각 행에 Job 대응
4. honesty_footer: "child_lock은 시뮬레이터 상태 전이 — 안전 기능 아님(NFR5)"

### F2 — "잃어버리면요?" (S7, 가장 날카로운 질문의 답)

1. 폐기 전: 온바디에 데이터 있음 · 복원 가능 ✓
2. 폐기 실행 (오프라인 강제 안에서)
3. **evidence_block**: 축1 복원 시도 ✗ / 축2 잔류 0건 — 배지 없음
4. 재온보딩 성공 ✓ ("재설정 = 폐기 → 재온보딩" 경로)
5. honesty_footer: "**원격 소거는 없다** — 캐리어 접근 전제. 1차 방어는 기기 PIN"

## 손목 1장 (제품 UI — 설계안, 미구현)

- 장면: 야간모드 1개만. 구성은 DESIGN.md "손목 1장" 절.
  목업: [mockups/wrist-sketch-night.html](mockups/wrist-sketch-night.html)
  (충돌 시 본 계약이 우선). GPT 컨셉 목업 6장은 `imports/` 보관 —
  판정표는 memlog 참조 (야간 장면 채택 / 원격·배지·무조건형 보안 문구 금지).
- **별칭 규칙 (DECISIONS.md 열린 질문 1·2의 답)**:
  - 별칭("안방 에어컨")은 **표시 기기 로컬 전용 설계** — 프로필·캐리어·이동 경로
    진입 금지. 프로필 차단은 구현·테스트됨(`FORBIDDEN_KEY_FRAGMENTS` 무변경),
    표시층 자체는 **미구현**.
  - 무별칭 폴백 = device_type 한글화("에어컨").
  - `owner` 과잉 차단 **유지** — 별칭이 프로필 밖에서 해결되므로 예외 불필요.
  - 별칭 비이전은 결함이 아니라 FR7의 증거 — 이사하면 "안방"이 아니게 되므로
    재명명이 UX 정합이다.

## 미해결 (창작하지 않은 것)

- 프로젝터 최소 폰트 크기 — 리허설 실측 대기
- 실기기(가민) 화면 — 범위 밖, 참조 어댑터 표기 유지
- 제품 폰 앱 화면 전반 — 창작 금지 결정 유지 (손목 1장 외)
