## 1. PRD — 제품 요구사항

### 1.1 한 줄 정의

> **집의 상태(홈 프로필)를 클라우드가 아니라 사용자의 몸(워치)에 귀속시켜,
> 서버·앱·계정이 없어도 집이 나를 따라오게 하는 온바디 홈 프로필.**

### 1.2 문제 (CX 보고서 실측 — [CX_분석결과](../final-output/CX_분석결과.md))

**공개 앱스토어에서 직접 크롤링한 리뷰 74,434건** → 부정 리뷰 7,625건 토픽 분석:

| Pain | 내용 | 실측 |
|---|---|---|
| **P-1 클라우드 SPOF** | 앱/서버가 죽으면 가전 제어 불가 | 부정 리뷰의 **43.4%** |
| **P-2 설정 휘발** | 재설치·초기화 시 홈 설정이 소멸 | 1.37% — 경쟁(SmartThings) 대비 **2.0배** |
| **P-3 진입장벽·개인정보** | 계정·약관·개인정보 강제 | 6.2% (토픽 배정 기준 0.5% — 병기) |

**진단(POV)**: 개별 기기 버그가 아니라 **홈 프로필이 클라우드 계정과 앱에 종속된 구조**가
세 Pain의 공통 원인이다.

### 1.3 해법 원리 (Key Accelerator)

공통 원인 한 곳을 쳐서 셋을 동시에 푼다:

> 홈 프로필을 온바디 디바이스(워치, 캐리어 중립)에 귀속 + 가전과 로컬 통신
> → P-1(서버 무관 동작) · P-2(프로필이 사용자를 따라다님) · P-3(서버가 원본 미보유)을
> **단일 아키텍처로 해소**

### 1.4 타깃

| 등급 | 페르소나 | 근거 |
|---|---|---|
| **T1 (근거)** | **Night Keeper** — 밤에 앱으로 집을 지키려다 앱에게 배신당하는 사람 | 리뷰 실증: 야간 맥락 7.6%, P-1 43.4%, 이탈 선언 5.5% |
| T2 (가설) | Quietly Home · 30대 맞벌이 | **"가설 — 검증 미실행(NDA)"** — [SURVEY_TRACK_CLOSURE](../SURVEY_TRACK_CLOSURE.md). 모수 배경만 `[공개출처]` 근사: 30대 맞벌이 63.3% |

인구통계는 전 등급 미확인(리뷰 컬럼: review/rating/date/likes). 지어내지 않는다.

### 1.5 요구사항 (제품 관점 — [biz-docs 04](biz-docs/04_요구사항정의서.md)의 FR/NFR 재사용)

| ID | 요구 | 근거 Pain |
|---|---|---|
| FR-1 | 워치에 홈 프로필 저장 (키당 4,096B·총 128KB 예산) | P-2 |
| FR-2 | 근접 시 프로필 기반 기기 제어 — **서버 무경유** | P-1 |
| FR-3 | 신규 환경 이주 (기기 맵핑 재결합) | P-2 |
| FR-4 | 무계정 로컬 온보딩 — 동의 범위 로컬 한정 | P-3 |
| FR-5 | 프로필 폐기·복구 (분실 시나리오) | 신뢰 전제 |
| FR-6 | 다인 가구 각자 프로필 (부부 2프로필) | Quietly Home |

NFR: 릴레이/재생 공격 방어(THREAT_MODEL) · 근접 제어 지연 2초 이내 `[가정]` ·
**정직 표기(프로젝트 헌법)** · 벤더 격리(CARRIER_INTERFACE).

### 1.6 지켜야 할 강점 (설계 제약)

strengths.csv 실측(전부 평점 5): 다기기 호환성 · 원격 조작 · 원격 모니터링.
**처방이 이 강점을 깨면 안 된다** — "원격"은 클라우드 경유가 아닌 로컬 대안이 있어야 유지된다.

## 2. MVP 범위 — 최소한으로 완성할 핵심 기능 범위

### 2.1 선정 기준

**Key Accelerator의 주장을 증명하는 데 필요한 최소한.** 주장이 "한 곳을 치면 셋이 풀린다"이므로,
MVP 범위는 **P-1·P-2·P-3 각각에 증명 경로 하나씩**이 있어야 하고 그 이상은 필요 없다.

### 2.2 범위 내 (구현·검증 완료 — 2026-07-29 기준)

| # | 기능 | 증명하는 Pain | 상태 |
|---|---|---|---|
| 1 | 온바디 홈 프로필 코어 — 스키마 v1.0.0·저장·크기 예산 | P-2 | ✅ 426 passed |
| 2 | 캐리어 중립 전송 (CARRIER_INTERFACE, 벤더 격리) | P-1·P-2 | ✅ 경계 테스트 통과 |
| 3 | 서버리스 적용 — 가전 **시뮬레이터** + `offline_guard` 오프라인 강제 | P-1 | ✅ 증거 2종([OFFLINE_EVIDENCE](../OFFLINE_EVIDENCE.md)) |
| 4 | 무계정 로컬 온보딩 + 동의 범위(CONSENT_SCOPE) | P-3 | ✅ demo_onboard |
| 5 | 이주 시나리오 (demo_relocate) · 폐기/복구 (demo_revoke) | P-2·신뢰 | ✅ 데모 10종에 포함 |
| 6 | 다인 프로필 병행 (demo_quietly — 충돌 해소는 범위 외 명시) | FR-6 | ✅ |

**완성 판정 근거**: 회귀 426 passed · 오프라인 증거 2종 · 시나리오 데모 10종 · PoC/TRL 4(코어).

### 2.4 MVP 범위가 증명하지 못하는 것 (정직 표기)

- **실기기 동작** — 가전이 자체 제작 시뮬레이터다. "유사 운용환경" 미달(TRL 5 아님)
- **타깃 실재** — T2는 검증 미실행(NDA). Pain **일반화**도 주장 불가([SURVEY_TRACK_CLOSURE §2.1](../SURVEY_TRACK_CLOSURE.md))
- **성능 실측** — NFR-2(2초)는 `[가정]`
