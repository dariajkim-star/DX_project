# 서비스 흐름도 — ThinQ OnMe

작성 2026-08-06 (파티) · 산출물 특강 요구 산출물 4번 · p.26 원칙 준수
(핵심 기능만·사용자/시스템/외부 구분·YES/NO 분기·Mermaid).

> **AI 초안 — 최종 책임은 팀.** ⚠️ 소급 작성 — 흐름은 데모 코드 실동작에서 역추출.
> [ARCHITECTURE_FLOW](../ARCHITECTURE_FLOW.md)(코드 층 구조)와 다른 문서다 —
> 이쪽은 **사용자 관점** 흐름이다. 범례: 🙂 사용자 행동 / ⚙️ 시스템 처리 / 📺 가전(외부·시뮬레이터).

핵심 흐름 3개만 그린다 — Pain 하나당 하나 (P-1 → 근접 적용, P-2 → 이주, P-3 → 온보딩).

---

## 1. 근접 프로필 적용 — P-1 반박 (UC-003, `demo_night`)

**대비점: 기존 구조는 "앱 실행→로그인→서버 응답 대기"가 선행하고 서버 장애 시 전체 불능.
이 흐름에는 그 경로 자체가 없다.**

```mermaid
flowchart TD
    A[🙂 워치 착용한 채 가전에 접근] --> B{⚙️ 근접 감지}
    B -- NO --> A
    B -- YES --> C[⚙️ 캐리어가 프로필 청크 전송]
    C --> D{📺 서명·신선도 검증}
    D -- "서명 불일치 / 재생 감지" --> E[📺 적용 거부 — 상태 불변]
    D -- "폐기된 프로필" --> E
    D -- 통과 --> F{⚙️ 야간 모드 조건?}
    F -- YES --> G[📺 야간 프로필 적용]
    F -- NO --> H[📺 표준 프로필 적용]
    G --> I[📺 적용 결과 통지 — 종료]
    H --> I
```

> **이 흐름 어디에도 서버·클라우드·로그인 노드가 없다.** 오프라인 강제 환경에서
> 네트워크 호출 0건으로 실증([OFFLINE_EVIDENCE](../OFFLINE_EVIDENCE.md)).

## 2. 이주 재결합 — P-2 반박 (UC-004, `demo_relocate`)

```mermaid
flowchart TD
    A[🙂 이사 후 신규 가전에 접근] --> B[⚙️ 미매핑 기기 감지]
    B --> C{⚙️ 프로필 내 대응 기기 타입 존재?}
    C -- NO --> D[⚙️ 해당 설정 보류 목록 — 버리지 않음]
    C -- YES --> E{⚙️ 동일 타입 복수?}
    E -- YES --> F[🙂 대상 기기 선택]
    E -- NO --> G[⚙️ 매핑 제안 생성]
    F --> G
    G --> H{🙂 매핑 승인?}
    H -- NO --> D
    H -- YES --> I[⚙️ 맵핑 재결합 — 프로필 원본 불변]
    I --> J[📺 이후 근접 시 흐름 1로 적용 — 종료]
```

> **재등록·재가입 노드가 없다.** "핸드폰 초기화하고 재설치하니 제품이 전부 없어짐"(P-2
> 대표 인용)의 구조적 반대.

## 3. 무계정 온보딩 — P-3 반박 (UC-001, `demo_onboard`)

```mermaid
flowchart TD
    A[🙂 온보딩 시작] --> B[⚙️ 로컬 프로필 골격 생성]
    B --> C[⚙️ 동의 범위 제시 — 로컬 항목만]
    C --> D{🙂 항목별 동의?}
    D -- 일부 거부 --> E[⚙️ 거부 키 제외하고 구성]
    D -- 전체 동의 --> F[⚙️ 전체 구성]
    E --> G{⚙️ 저장 예산 검사 128KB}
    F --> G
    G -- 초과 --> H[⚙️ 생성 거부·사유 안내 — 종료]
    G -- 통과 --> I[⚙️ 프로필 활성화 — 종료]
    I -.-> J["(서버 계정 생성 노드 없음 —<br/>회원가입·약관·개인정보 제출 부재)"]
```
