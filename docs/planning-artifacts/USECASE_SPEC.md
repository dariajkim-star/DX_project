## UC-001 계정 없이 시작하기 (로컬 온보딩)

| 항목 | 내용 |
|---|---|
| 액터 | 사용자 |
| 목적 | 회원가입·약관·개인정보 제출 없이 홈 프로필 사용을 시작한다 (P-3 반박) |
| 사전 조건 | 워치(캐리어)에 프로필 없음 |
| 사후 조건 | 워치에 초기 프로필 생성됨. **서버에는 아무것도 생성되지 않음** |
| 기본 흐름 | ①사용자가 온보딩 시작 ②시스템이 로컬에서 프로필 골격 생성 ③시스템이 동의 범위를 **로컬 항목만** 제시 ④사용자 동의 ⑤프로필 활성화 |
| 대안 흐름 | 동의 항목 일부 거부 → 해당 키만 제외하고 생성 |
| 예외 흐름 | 저장 공간 예산(128KB) 부족 → 생성 거부·사유 안내 |
| 관련 FR/NFR | FR-4 / NFR-3(정직 표기) · 검증: CONSENT_SCOPE 대비 요구 항목 diff=0 |
| 근거 데모 | `demo_onboard` (Story 4.1) |

## UC-002 내 설정을 몸에 지니기 (프로필 저장·휴대)

| 항목 | 내용 |
|---|---|
| 액터 | 사용자 |
| 목적 | 집의 상태(온도·루틴·기기 설정)를 내 소유물로 몸에 보관한다 (P-2 반박) |
| 사전 조건 | UC-001 완료 |
| 사후 조건 | 변경 사항이 워치 프로필에 반영·서명됨. 서버 사본 없음 |
| 기본 흐름 | ①사용자가 설정 변경 ②시스템이 스키마 검증(금지 키 차단 포함) ③크기 예산 검사(키당 4,096B·총 128KB) ④저장·서명 |
| 대안 흐름 | — |
| 예외 흐름 | 스키마 위반(금지 키 lat/lon·"owner" 등) → 거부 / 예산 초과 → 거부·현재 사용량 안내 |
| 관련 FR/NFR | FR-1 / NFR-4(벤더 격리) |
| 근거 데모 | 프로필 코어 (Epic 1, 스키마 v1.0.0 — 426 passed의 중심) |

## UC-003 다가가면 집이 맞춰지기 (근접 제어, 서버 무경유)

| 항목 | 내용 |
|---|---|
| 액터 | 사용자 · 가전(외부) |
| 목적 | 앱을 열지 않고, 서버 없이, 내 설정대로 집이 맞춰진다 (P-1 반박 — 발표 클라이맥스) |
| 사전 조건 | 유효 프로필 보유 + 가전과 근접 |
| 사후 조건 | 가전 상태 = 프로필 값. **네트워크 호출 0건** (오프라인 강제 환경에서 증명) |
| 기본 흐름 | ①근접 감지 ②캐리어가 프로필 전송(청크) ③가전이 서명·신선도 검증 ④가전이 상태 적용 ⑤적용 결과 통지 |
| 대안 흐름 | 야간 모드 조건 충족 시 야간 프로필 우선 적용 (`demo_night`) |
| 예외 흐름 | 서명 불일치·재생(replay) 감지 → 거부(NFR-1) / 폐기된 프로필 → 거부(UC-005 연동) / 전송 중단 → 부분 적용 없이 롤백 |
| 관련 FR/NFR | FR-2 / NFR-1(릴레이 방어)·NFR-2(지연 2초 `[가정]`) |
| 근거 데모 | `demo_night` (Story 2.4) · 오프라인 증거 2종([OFFLINE_EVIDENCE](../OFFLINE_EVIDENCE.md)) |

## UC-004 이사해도 집이 따라오기 (신규 환경 재결합)

| 항목 | 내용 |
|---|---|
| 액터 | 사용자 · 가전(외부) |
| 목적 | 이사·기기 교체 후 재등록 없이 기존 설정이 새 기기에 이어진다 (P-2 반박) |
| 사전 조건 | 기존 프로필 보유 + 신규 환경의 미매핑 가전 |
| 사후 조건 | 신규 기기에 기존 설정 매핑 완료. 프로필 원본은 불변 |
| 기본 흐름 | ①신규 가전 근접 ②시스템이 기기 타입 매칭(맵핑 재결합) ③사용자에게 매핑 제안 ④확인 후 적용 (이후 UC-003 «include») |
| 대안 흐름 | 동일 타입 복수 기기 → 사용자가 선택 |
| 예외 흐름 | 대응 타입 없음 → 해당 설정 보류 목록으로 안내 (버리지 않음) |
| 관련 FR/NFR | FR-3 / NFR-4 |
| 근거 데모 | `demo_relocate` (Story 3.2) · `demo_reinstall` (Story 3.1) |

## UC-005 잃어버리면 무효화하기 (폐기·복구)

| 항목 | 내용 |
|---|---|
| 액터 | 사용자 |
| 목적 | 워치 분실 시 프로필을 무효화해 "잃어버리면요?" 반박에 답한다 (신뢰 전제) |
| 사전 조건 | 유효 프로필 존재 |
| 사후 조건 | 구 프로필 전면 무효(가전이 거부) · 복구 시 새 서명으로 재발급 |
| 기본 흐름 | ①사용자가 폐기 선언 ②시스템이 폐기 토큰 발행 ③가전이 이후 구 프로필 거부 ④(복구) 새 캐리어에 재발급 |
| 대안 흐름 | 복구 없이 폐기만 — 무계정이므로 서버 측 삭제 절차 자체가 없음 |
| 예외 흐름 | 폐기 전파 전 접근 시도 → 신선도 검증으로 차단(잔여 한계는 THREAT_MODEL에 문서화) |
| 관련 FR/NFR | FR-5 / NFR-1 |
| 근거 데모 | `demo_revoke` (Story 4.4) · [REVOCATION](../REVOCATION.md) |
